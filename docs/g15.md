# G15 — servidor central (Dell G15, Windows 11)

Único servidor do ai-memory (versão 2.3.2).

## Topologia local

- Windows 11 com Tailscale ligado.
- WSL2 Debian hospeda o Docker.
- Container: `ai-memory`.
- Volume Docker: `ai-memory-data`.
- Dados persistentes no container:
  - Wiki Git: `/data/wiki`
  - Banco SQLite: `/data/db/memory.sqlite`
- No host WSL, o volume aparece em:
  `/var/lib/docker/volumes/ai-memory-data/_data/wiki`
  (registrado como remote `source` no clone de backup).
- O servidor fica acessível aos outros dispositivos pelo Tailscale.

## Verificar / iniciar o ambiente

```bash
# no WSL2 Debian do G15
docker ps --filter name=ai-memory
docker volume inspect ai-memory-data

# o backup espera estes remotes no clone ~/backups/ai-memory-wiki:
git remote -v
# origin  git@github.com:diasgarcia/ai-memory-wiki-backup.git
# source  /var/lib/docker/volumes/ai-memory-data/_data/wiki
```

Se o container não estiver no ar, suba pelo seu compose/serviço habitual
e confira com `docker ps`. Não altere volume, imagem ou cron por esta branch —
aqui é só documentação.

## Backup (referência)

- Clone de backup: `~/backups/ai-memory-wiki`
- Script real: `~/bin/backup-ai-memory.sh`
  (cópia versionada em `scripts/backup-ai-memory.sh`)
- Cron (WSL ligado):
  `0 * * * * /home/diasgarcia/bin/backup-ai-memory.sh >> /home/diasgarcia/backups/ai-memory-backup.log 2>&1`
- O script usa `alpine/git` com `ai-memory-data` montado como somente leitura,
  gera um bundle, faz `git fetch <bundle> master` + `git reset --hard FETCH_HEAD`
  no clone e dá `git push origin master`.

Nenhum token ou credencial é versionado. Não documente o token de autenticação.
